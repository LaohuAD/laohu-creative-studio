可执行验收清单：

1. **共享编辑面**：从 Hypit 模块点击“打开画布编辑” / “Open canvas editor”，在同一全屏编辑标签中使用共享画布节点。若通过同源 iframe 嵌入，核对父页与 iframe 的项目 ID、节点 ID、持久化记录、模型选择、执行和任务查询都落到同一真源；不得通过 DOM 共存误判为数据共享。
2. **范围隔离**：旧 Hypit 原生作品工程、Studio、Comments、项目 ID、素材、历史任务和结果保持原归属。迁移只作用于旧六槽生成设置；重复迁移幂等，中断后可安全恢复，不复制任务、不重建作品。
3. **重置保护**：点击“重置配置” / “Reset configuration”后，当前模块设置图的节点、连线、参数/设置、日志和视口恢复为空初始值，同时保留画布身份、修订与迁移标记，避免再次导入旧六槽配置；`assets/input`、`assets/output`、其他作品、旧 Hypit 工程、历史结果和已提交/在途任务均保留。比较重置前后真实目录清单和哈希；不得读取或输出媒体正文。
4. **素材锁与自动适配**：未锁时按明确类型和引用身份自动适配；锁只阻止 Hypit 自动替换该素材绑定，不限制普通画布手动编辑、其他模块读取或素材管理。没有可匹配候选时不得覆盖现有引用或假装适配成功；多个明确的 `@` 引用不是歧义且保留顺序；仅在来源或目标确实无法唯一定位时提示错误，且不静默选择或重排。
5. **固定与动态端口**：固定输入端口仅保存一条连线；添加相容新线时旧线被原子替换，静态类型不兼容须拒绝且不留下半条连线。动态 AI 应用端口按实际 Schema 暴露输入/输出字段，允许接入任意 Hypit 用途；不按用途静态过滤字段，不由名称、Schema 标签或声明用途猜能力，不强制用途绑定。精确保留用户选择的 `targetFieldKey`；未知或与目标用途静态类型不同的动态字段仍可编辑连接，不被隐藏或重写。实际运行仍按 Schema 校验必填输入和字段格式，并按真实返回类型校验目标用途；错类、未知或缺少有效目标结果须明确失败，不覆盖既有结果。节点/API 应用保存值是默认值，单次 Hypit 请求只以精确字段键覆盖本次任务；省略的值沿用默认，未知键或错误格式拒绝，任务覆盖不得回写设置；不增加参数锁或独立参数绑定表。
6. **六用途抽屉与输出节点**：右侧抽屉承担添加六种用途节点；再次选择已存在的用途应聚焦对应已有输出节点，不聚焦抽屉充当结果面板，也不创建重复节点。检查每个固定输出节点的端口数量、点击路径、焦点和窄屏可达性。
7. **普通运行自动认证，不提供独立测试入口**：输出端口没有“测试/验证”按钮或第二个运行入口。红表示用途端口未连接；黄表示已连接但尚无与当前来源配方相符的成功普通运行记录，可以运行来源执行节点；绿表示来源节点经共享 Studio/Agent 服务普通执行成功，服务端任务快照仍匹配当前来源闭包配方，并且结果收集器保存了实际、可访问且类型符合该用途的受管结果。运行接受时只绑定来源执行节点、依赖闭包配方及请求快照，不要求输出端口或 slot 已存在；用户可先普通运行，再接入输出端口，接线后由服务端按端口用途与真实结果类型投影状态。配方指纹覆盖会影响执行的模型、参数、输入和依赖，不包括布局或输出连线；依赖配方改动、解绑、任务失败/取消、错类或缺少受管结果均不得标绿。迟到的旧配方结果不能让新配方变绿。不能把客户端 `succeeded`、`runRef`、画布上的结果 ID 或用户手点“通过”当成成功凭证。普通运行仍保留结果、历史与取消入口；关闭编辑页不取消服务端已接受的任务，轮询与恢复继续使用原任务 ID，不重复提交。
8. **`@` 多输入顺序**：覆盖零、一、多条显式文本引用，以及图片/视频/音频混合引用、重复类型、重排和保存重开。画面显示顺序、`@` 序号、预检输入、提交 payload 中各类型数组顺序必须逐项一致；多个明确引用不被误判为歧义，也不按对象或集合遍历顺序漂移。
9. **依赖闭包与并发快照**：运行指定目标只执行其依赖闭包，不触发无关节点或兄弟生成；共享上游只运行一次。并发目标按 taskId 隔离提示、引用顺序、模型、参数、workflow/schema 快照、结果和错误。任务提交后修改设置或重置图不改变在途请求。
10. **运行时失败与重试**：以假供应商计数器覆盖“已接单但客户端超时”、查询失败、worker 重启、结果类型错误。恢复应查询/恢复原 taskId，不能自动再次提交可能收费的调用；同一 `client_operation_id` 重复请求不得二次 submit。明确手动重试则创建独立新任务且保留旧结果。错误和恢复入口清楚显示，中英文一致。
11. **多标签自动保存与后台任务**：同一项目开两个标签，验证自动保存后双方同步；不同节点的并发变更均保留，同一字段的冲突不可静默丢写，须有可观察的冲突/恢复路径。旧响应不得覆盖新选择。关闭编辑标签后后台已提交任务继续，重开可查看原状态与结果。
12. **布局与端到端**：在 1440/1280/390 宽度及中英文界面检查添加抽屉、节点、固定/动态连线、焦点、状态提示和保存/错误入口，无横向溢出或不可达控件。先用假 callback 完成正向及失败路径，再用实际 DOM/原生 Hypit 入口确认共享契约；不把 fixture 通过写成真实供应商验收。
13. **生成候选与后续处理分支（本轮补充决定）**：Hypit 配置图中的 API 生成模型候选仍须满足用户启用、完整模型契约、节点输入/输出要求及对应 Hypit 用途，沿用 `hypit_profile_reasons`；不适用的生成模型须从 Hypit 选择器隐藏，后端也拒绝绕过筛选的请求，但不得从普通画布全局启用列表、共享能力档案、凭据或用户配置中删除。查询、下载、放大、增强、字幕等专用工具不能冒充生成模型；普通画布的独立处理节点仍可接在实际生成节点之后，作为后续流程步骤。AI 应用/工作流由用户连接到目标用途，不按名称、Schema 或声明标签预判适用性，执行后按真实结果类别和宿主调用契约验证。工作流执行定义和安全 Schema 不限制画布已有的处理步骤；依赖图缺少实际生成输入时，须返回可行动的不可调用错误。

### 全局模型清单与配置画布（2026-10-05）

模型启用状态只有一个真源：沿用现有 `data/api_providers.json` 中按媒体用途保存的平台模型列表及 RunningHub 分站列表，不另造模块级白名单。`canvas-settings` 是无输出端口的共享画布配置模式，通过标准画布 revision/CAS 保存图，并使用精确的模型启停接口更新上述列表；重置只清配置图，不触碰启用清单、能力档案、凭据、普通画布和在途任务。管理目录列出当前已配置且平台/站点启用、具备完整严格可运行档案的模型选项，包括当前尚未启用的项目；它不等同于供应商未核验原始目录，也不允许启用缺少安全执行契约的模型。RunningHub 的 AI/CN、provider、部署与媒体用途以稳定 `option_id` 区分。

Canvas、Hypit、Article 和 Agent 共用该启用状态，但仍各自按输入、输出、操作与宿主用途筛选。模型顺序和参数字段展示偏好保存在 `smart-canvas/personalization`，只是展示信息，不改变启停、节点精确选择、参数值、运行优先级或已提交快照。模型家族、平台、运行模式和参数字段均通过拖拽柄排序；普通画布只读顺序，不提供启停或排序控件。模型及 RunningHub AI/CN 站开关都保留原生勾选、标签和键盘状态，同时用绿/红分别表示启用/关闭。`parameterPresentation[option_id][parameter_key]` 只允许 `width`（`full` / `half`）以及可选的非负整数 `order`；不能写参数显隐、默认值、枚举或实际值。所有已核验 Schema 参数都必须保持可见；旧 `visible:false` 只兼容读取并忽略，后续保存会剔除。必填且没有有效默认值的参数不能隐藏，也不能仅因标记为高级项而折叠。全局及单模型展示偏好重置会递增 `reset_epoch`；旧页面的缺失或过期 epoch PUT 返回冲突，避免把重置前的排序恢复，模型启用清单保持不变。验收须验证禁用立即阻止普通入口的新候选与新提交、旧选择及能力档案/凭据仍保留、在途任务不变；排序不改 `option_id`；管理页读取、排序、重置均无生成提交。

音乐成品继续使用共享素材/结果索引和稳定 ID 引用；音乐项目不复制媒体文件，不把磁盘路径作为项目接口。API 凭据、模型候选、预检、任务与结果收集沿用工作台共享链路。音乐生成配置采用一张模块级设置图，复用共享画布编辑器与执行器；不为每首歌创建独立隐藏画布，不建立第二套凭据、生成执行器、任务或素材库。Agent 接入绑定具体音乐项目，只读取当前契约并等待用户的创作要求；连接、读取、试听和普通保存不触发生成。设置图重置不得删除歌曲内容、版本、共享结果或已提交任务。

音乐接口以运行服务 OpenAPI 为准：`GET/PUT /api/studio/music/{project_id}` 读取或按 `expected_revision` 更新歌曲；`GET/POST /api/studio/music/{project_id}/generations` 列出或提交任务；`GET /api/studio/music/{project_id}/generations/{run_id}` 恢复原任务并返回当前歌曲。项目列表使用共享 `GET /api/studio/projects?module=music`。配置图为固定 `music-settings`：`GET /api/studio/music/settings-canvas`、`POST /api/studio/music/settings-canvas/reset`；动态节点安全字段目录为 `GET /api/studio/music/settings-canvas/input-fields?output_node_id=...`，Agent 命令沿用 `POST /api/agent/canvases/{canvas_id}/commands` 并指定 `canvas_id=music-settings`。

歌曲记录以 `source_sha256` 标识当前标题、歌词、风格、备注、封面提示及输入素材引用；源内容修改时追加不可变 `source_versions`，快照必须保留参与哈希的 `score_refs` 身份引用，使其内容与保存的指纹可对应。生成接受快照也保留这些乐谱引用，但它们不自动成为模型执行输入。历史音频和封面项只保存已解析的共享 `asset_id` / `result_id`、服务端生成的来源快照、接受 revision 与任务身份。`PUT` 可用 `audio_refs`、`cover_refs` 接入外部 Agent 已有结果，服务器会重新解析素材，不接受客户端伪造的 `run_id`、来源快照或版本状态。`score_refs` 只接受 `abc`、`musicxml`、`midi`，服务端核对扩展名、MIME 与真实内容；`timed_lyrics` 按音频版本 ID 保存秒级 `start`、可选 `end` 和 `text`。结果入库本身不自动选择版本。

生成请求为 `{purpose,slot,output_node_id,client_operation_id,request,base_revision?}`；歌曲固定 `purpose=song, slot=music`，封面固定 `purpose=cover, slot=image`。`request` 仅允许共享节点契约中的 `parameters` 或动态工作流的 `input_fields`，不接受客户端直接指定来源、运行状态或素材历史。静态歌曲节点按确切模型档案映射：`music_song` 使用已保存歌词作 prompt，并要求档案确认 `style_prompt` 参数映射；纯 BGM `music` 以已保存风格作 prompt，歌词存在时拒绝，不额外伪造风格参数。动态应用/工作流必须为实际存在的字段提供精确 `{node_id,targetFieldKey}`，歌曲歌词与风格按可用内容映射，参考音频只指向受管共享素材。单次输入在 HypitFlowRunner 私有任务副本中覆盖同一精确字段的既有素材引用/连线，并重算本次依赖闭包；持久配置图及其修订不变。

每个 `client_operation_id` 在整张音乐配置图内唯一；相同请求重放返回原任务，不同项目、用途、端口、输入或基准 revision 冲突为 409。服务端保存接受时的来源与配置图快照；查询原 `run_id` 可恢复任务并重试共享结果关联，不重复提交模型。只有共享收集器登记、结果引用仍可访问且媒体类型符合歌曲音频或封面图片时，才追加版本；失败或错类结果不得伪装成成品。验收使用合成素材和注入式假执行器，不表示真实供应商兼容或费用为零。定向回归：`./.venv/bin/python -m unittest tests.test_studio_music_integration tests.test_module_slot_contracts -v`；必须验证真实 `HypitFlowRunner` 执行路径、OpenAPI 暴露的路由、标准与动态字段映射、`False`/`0` 参数、私有副本字段覆盖、revision 冲突与同任务恢复。

### 2026-10-10 剧本与小说模块

剧本、小说使用共享项目目录和 `StudioProjectStore` revision，不引入数据库或第二套生成服务。正文按 UTF-8 内容哈希保存为不可变 Markdown blob；项目 JSON 保存目录、修订/操作回执和索引。缺失或哈希不匹配的正文读取会报错，不投影为空文本。剧本模块管理正文及集、场、分段，分段范围按 Unicode 码点计算；替换分段原子更新正文、后续偏移与来源指纹。结构化完整草稿时保留尚未拆分的正文。

本轮增加显式 Markdown 交换契约 `laohu-manuscript-v1`，不更换 Store 的真源：剧本导出 `# {集标题}` / `## {场标题}`，小说导出 `# {卷标题}` / `## {章标题}`，任意目录标题均按原目录值处理且导入新建 ID、不按标题猜身份。导入走各模块 `commands` 的 `import_markdown` `{body_markdown,replace}`，且 `replace` 是严格布尔值；空项目用 `false`，已有内容必须 `true`，旧树与正文引用归档，命令回执返回规范化导入全文的 `source_sha256`，之后可通过本项目专用 Markdown history 路由读回。输入 CRLF 规范为 LF。正文中保留标题应从 `###` 起；导出碰到会与目录冲突的正文 H1/H2 返回 409 `MARKDOWN_FORMAT_CONFLICT`，不吞正文。剧本仅将独立 `---` 行作为片段边界；紧邻分隔线前后各一个 LF 属于语法，额外 LF 留在段正文。无分隔线场次作为单段，空正文也有 `0..0` 空段；段编辑拒绝把独立 `---` 存成正文。`create_segment` 允许空正文/标题，`update_scene(scene_id,body_markdown)` 按分隔线重建范围；只有同位置且正文精确相同的段保留 ID。该格式在目录标题、换行和分隔线语法上可规范化，不宣称原始 Markdown 每个字节都逐字往返；原始规范化全文历史保留可供追溯。

结构标题扫描忽略 fenced code 中的 `#` / `##`，因此代码示例里的行不会被误拆成集、场、卷或章。ATX 标题在标题名后以空格/制表符加井号串闭合时，导入会去掉闭合井号并按规范标题导出；井号与标题名相连时仍属于标题名。该解析规则不改变剧本分段：独立 `---` 无论是否处于代码围栏内仍是唯一片段分隔符。所有手工目录操作与 Agent 共用相同命令 API：用户可添加合法集/场/段或卷/章、重命名目录及编辑场、段、章正文；写入依赖当前 `revision` 和唯一 `request_id`，409 时重读并保留未保存草稿，新建项从 `created_ids[client_ref]` 定位。目录不是独立磁盘文件或媒体素材库条目。

剧本只在用户明确要求后通过 `POST /api/agent/canvases/{canvas_id}/commands` 的 `import_script_segments` 导入普通画布。一次画布保存同时生成正文/分段文本素材、story 组织连线、`sourceRef` 来源快照和 `production.role="segment"` 创作进度登记；不触发模型。画布回执先于源项目读取核对，相同请求可在进程重启、源项目已删除或客户端丢失回执时恢复。导入不双向同步；源内容变化由 append 冲突提示，用户可明确选择保留旧节点并新增快照。

`sourceRef` 属于画布节点正文，`scriptImports` 属于画布快照目录：前端保存、服务端 Canvas PUT、多标签同步与工作流 JSON/ZIP 导入导出都要保留它们。旧客户端省略可选 `script_imports` 时，服务端沿用已保存值；工作流选中导出只投影相关节点的导入快照，不传来源画布的命令回执，导入时节点 ID 与快照引用一同重映射。节点手工复制保留可追溯的 `sourceRef`，但把 `production` 角色清为普通素材，不能伪装成原导入段或制造重复进度登记。

小说项目保存卷章正文、七类可选设定目录和用户明确记录的接续文档。人物及其他设定是一条自由 Markdown 文档，不是字段表。故事阶段锚点/`story_version` 与同一版本的 `edit_revision` 分离；锚点允许 baseline、unspecified、真实章节边界或真实时间线事件。设定版本基线与 `basis_refs` 都保存并校验来源内容指纹；依赖失配只标记 `needs_review`，不自动改写章节或改变故事阶段。manifest 仅投影紧凑目录与接续入口；context 返回显式置顶/接续及未排序候选，不用版本号、最新版本或章节序号判断设定是否适用于当前场景。无接续记录返回 `{exists:false,record:null}`。
