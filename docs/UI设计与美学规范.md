# 无限画布 UI 设计与美学规范

## 1. 文档定位

这份规范是“老胡无限画布”后续 UI 设计、页面重构和新功能开发的共同基线。它服务于真实的创作工具，不服务于营销首页、概念稿或装饰性视觉展示。

每次新增或修改界面前，必须先阅读本文件，并结合项目现有实现判断是保守优化、局部重构还是新增组件。不能因为参考了外部产品截图，就把外部产品的布局、命名或交互原样搬进来。

本规范与以下两套设计方法共同使用：

- `frontend-design`：先明确产品目的、使用人群、视觉方向和可记忆的设计重点，再实现真实可用的界面。
- `design-taste-frontend`：先审计已有页面和设计令牌，控制颜色、密度、圆角、动效和组件重复，避免模板化的 AI 界面。

## 2. 设计判断

### 2.1 产品类型

这是高频使用的 AI 创作工具。用户需要在画布中组织素材、连接节点、选择模型、配置参数并检查费用。界面首先要让人看得清、选得准、改得快，其次才是视觉个性。

### 2.2 视觉方向

采用有画室气息的创作工具语言，但先让文字清楚、颜色搭配舒服、信息层级明确，再考虑单一颜色是否足够醒目。默认身份 `studio-violet` 延续现有紫色画室方向；主题身份（`identity`，即一组配色）与浅色/深色外观分开选择，任何身份都需有适配浅色与深色的成套语义色。主题选择入口放在右侧面板，以卡片呈现颜色预览、主题名称和配色特征；面板只向用户提供浅色与深色选择并保留关闭操作，不提供撤销入口。已保存的旧 `system` 偏好继续兼容读取和解析；打开面板时显示当前解析出的浅/深选中态，不能自行改写存储，只有用户明确选择后才保存新模式。窄屏改用可关闭的底部面板。项目列表标题显示模块名，旁侧用简短双语文案说明模块用途，不显示动态项目数量或排序状态；桌面简介与标题同排，窄屏放到标题下方。搜索和高频操作仍集中在标题区域，宽屏同排、窄屏按可用宽度自然折行；Canvas 导入工程和回收站继续保留原按钮与点击行为，不再用独立说明卡重复解释。Canvas 与 Hypit 项目卡片都用两列两行展示打开、改名、Agent 接入、删除，按此顺序保留入口。左侧模块菜单需要扩展时，先减小相邻间距，保留文字可读和常规点击区域；不要为了密度把字缩小或把卡片操作挤到单独整行。标题操作区之后是必要指引，再显示项目卡片。温暖、鲜活来自颜色的明暗关系、使用面积、材料感与留白，不要求所有页面固定铺同一套紫、黄、红，也不让主色压过作品。真实画室与 Pinterest 图片可提供光线、材料、颜色面积和布局关系的参考；它们是视觉参考，不是创造力效果或界面可用性的证据，也不能照搬成品布局。

关键词是：温暖、鲜活、清楚、可专注、有层级、可恢复。不要用摆设或科技感装饰掩盖信息组织问题。

### 2.3 三个设计刻度

- `DESIGN_VARIANCE: 5`：允许画布具有自由空间，但节点、参数和设置页面保持稳定网格。
- `MOTION_INTENSITY: 3`：只使用状态反馈、弹层出现、按钮按压和必要的媒体预览动效。
- `VISUAL_DENSITY: 6`：创作工具需要较高信息密度，但每一项仍必须有呼吸空间，不能挤成一坨。

## 3. 视觉令牌

### 3.1 颜色

全项目共享稳定的语义色角色，不强制所有身份共用同一组色值。颜色系统分成两个独立选择：主题身份提供一套配色，外观模式在界面中由用户选择浅色或深色。底层继续兼容解析历史 `system` 偏好；打开主题面板不能重写原值，面板应标示系统当前解析出的浅/深模式，直到用户显式选择新的模式。默认身份为 `studio-violet`；当前主紫 `#7047EB`、暖白 `#FFF9F0`、浅紫 `#EEE5FF`、明黄 `#FFD34E` 与朱红 `#F15B49` 是它的起始色值，不是全项目的固定色表；只有在实际页面中搭配舒适、角色清楚且对比达标时才保留原值。需要时调整颜色或面积，不为保住单一色值而牺牲可读性，也不要求每个页面同时出现全部强调色。

| 语义角色 | 负责表达什么 | 主题身份与外观要求 |
| --- | --- | --- |
| `surface.canvas / panel / raised / muted` | 页面、面板、浮层和次级区域 | 每个身份分别提供浅/深表面层级；旧 `system` 偏好解析到对应外观，不能把浅色值直接铺进深色模式 |
| `text.primary / secondary / muted` | 标题、正文、辅助与弱化文字 | 与实际承载它的表面配对；普通文字达到 WCAG AA 4.5:1，大号文字达到 3:1 |
| `border.default / strong / focus` | 分隔、容器边界和键盘焦点 | 在两种外观下都可辨；焦点还要有轮廓或形状提示，不能只改颜色 |
| `brand.primary / action.primary` | 品牌识别与当前区域的主要操作 | 色值随身份变化；同一区域仍须只有清楚的主要操作层级，并验证其文字或图标配对 |
| `selection / creation.focus` | 当前选择与少量创作重点 | 面积和形状承担层级；不强制所有主题都用紫色或黄色，不以低对比小字承载信息 |
| `status.success / warning / danger / info` | 成功、提醒、错误和信息状态 | 语义跨身份保持稳定，文字或图标同时说明状态，不能拿装饰色替代状态色 |
| `decoration` | 非交互的画室材料感与视觉留白 | 只用在边缘或空状态；不能抢作品、阅读内容和高频控件 |

新增主题身份时，必须一次提供浅色和深色的完整角色值，并按真实前景/背景组合检查对比和整体搭配；不能只检验孤立色块，也不能把 Pinterest 或其他色板中的 HEX 直接当作可用界面配对。颜色搭配与舒适度要在真实页面、密集工作内容和浅/深/窄视口截图中判断；如果主色过亮、突兀或面积过大，先调整对应角色和使用面积。禁止无主次的大面积渐变、无语义彩色光晕、用颜色代替文字状态，或让多个强调角色同时占据同等视觉权重。

### 3.2 字体

- 普通中文界面使用系统字体栈：`-apple-system`、`SF Pro Text`、`PingFang SC`、`Microsoft YaHei`、`Segoe UI`。
- 页面标题、项目标题和节点主标题可以使用已随项目提供的 `Space Grotesk`，中文回退到系统字体。
- 模型 ID、API 地址、文件路径和 Token 使用等宽字体。
- 不新增远程字体，不把英文展示字体强行用于中文正文。
- 标题使用字重和间距建立层级，不使用夸张字号或负字距制造“设计感”。

### 3.3 尺寸与圆角

只使用三档圆角：

- 控件：`8-10px`。
- 节点和普通面板：`12-14px`。
- 全屏模态和大型编辑器：`14-18px`。

按钮可以使用轻微胶囊形，但页面不应让所有元素都变成胶囊。图标按钮必须保持稳定的正方形点击区域，桌面端建议 `32-36px`。

间距采用 4 的倍数。参数网格的列间距通常为 `6-8px`，面板内边距通常为 `12-18px`，页面大区间距通常为 `24-32px`。

### 3.4 阴影与边界

优先使用边界和表面差异表达层级，阴影只用于悬浮面板、节点和模态。阴影要轻、偏冷、带有背景色倾向，不能使用厚重的纯黑投影。

## 4. 页面结构规范

### 4.1 智能画布

- 画布是主要工作区域，背景保持安静。网格只能帮助定位，不能抢过节点和素材。
- 左上角保留返回入口和画布标题，右上角工具保持单行、统一高度、统一中心线。
- 右上角工具顺序按使用频率排列：价格对比、工作流、快捷键、日志、素材库。
- 工具按钮使用图标加短中文标签。标签不换行，不用装饰性副标题。
- 迷你地图、日志、价格对比和工作流面板属于工具层，必须拥有明确的层级和关闭路径。
- 价格对比面板必须支持输入即筛选、清空搜索恢复结果，以及在面板任意区域使用鼠标滚轮滚动；面板滚轮不得触发画布缩放。外部价格无法直接结构化展示时，查询按钮应复制精确模型 ID、按当前平台站点打开官方价格页，并用中英文提示说明“粘贴搜索并查看详情”的下一步操作。

### 4.2 节点

- 节点卡片、节点图标、节点标题、平台、模型和输入输出摘要必须有稳定的版式。
- 节点的尺寸由内容和可读性决定，不能为了塞进更多参数而无限拉高。
- 素材节点显示真实素材内容和原始名称；只有没有名称时才使用“图片1”“文本1”等类型化兜底名称。
- 执行节点显示节点类型、当前平台、当前模型和输入输出状态，不把技术字段堆在标题区域。
- 选中态使用一圈清楚但克制的边界，不使用大面积发光。

### 4.3 执行节点参数

五类执行节点共用同一套骨架：文本生成、图片生成、视频生成、音频生成和音乐生成。

- 一级入口固定为“平台、模型、运行模式”，即使只有一个运行模式也保留入口。
- 相同内容的目录刷新是 no-op：已打开的选择器不关闭或重建，不丢弃模型/平台浏览路径、草稿、搜索、筛选、焦点和滚动位置。目录确有变化时再局部更新，保留仍然有效的浏览状态。筛选标签的勾选只更新当前筛选和结果，选择器保持打开，焦点回到同一标签，不提交模型。
- 叶子提交后的异步保存可以晚于下一次打开选择器完成；较早的保存响应不得覆盖较新的选择，也不得重建已经重新打开的菜单或清空其中的筛选和焦点。家族与平台数量单独呈现为动态计数；切换中英文只更新本地化标签，不用 HTML 字符串覆盖计数节点或控制节点，也不改变真实数量。
- 未选择时显示参数名称，例如“分辨率”；选择后显示当前值，例如“2K”。
- 分辨率、时长、画面比例、质量、生成数量等同语义参数使用同一种入口样式。
- 桌面端优先使用紧凑网格。快捷参数按语义顺序排列：分辨率、质量或时长、画面比例。缺少某项时向左收拢，不留下空槽。
- 低频参数和高级参数放进齿轮入口，不直接平铺在节点底部。
- 参数入口只有用户点击后才展开，不因为悬停自动打开。点击另一个参数时关闭上一个，点击画布空白处关闭全部。
- 参数弹层默认从入口上方向上展开，始终高于节点、连线和画布工具。空间不足时才向下展开。
- 参数弹层不能被父容器裁切。打开时要提升参数面板和当前控件的层叠层级，并用实际命中测试确认用户点到的是弹层。
- 固定选项参数显示具体初始值，不显示含义不明的“默认”；可选自由输入允许留空，明确标示未填写，不发送空字段。
- 新建执行节点必须立即得到有效的平台、模型和运行模式默认值；用户切换上级选项后，下级自动选择第一个兼容默认值，不能留下只有平台或模型家族的半截状态。
- 必填枚举使用官方默认值或第一个官方选项，必填数值使用官方默认值或最小合法值，必填布尔使用官方默认值或“否”。已有模型因输入组合变化而失效时不得静默换模型，必须提示用户重新选择。
- 上游任务 ID、素材 ID、自由文本等依赖真实上下文的必填内容不得伪造默认值；这类运行模式没有安全默认值时，不得作为新节点的优先默认模式。
- 只有官方 Schema 明确支持的参数才进入界面，不能根据模型名称猜测参数。
- 平台、模型、运行模式等已经由一级入口确定的值，不得作为协议字段再次出现在齿轮参数中，也不得要求用户重复手填。
- 参数问号使用悬停和键盘聚焦浮层，不得点击后在参数卡片中插入一行说明、改变卡片高度或挤动其他控件。浮层必须脱离滚动容器并保持最高可交互层级。
- 参数说明必须回答“它控制什么、什么时候需要修改、会影响结果、耗时还是费用”。禁止使用“设置此参数的输入内容”“选择参数值”等只重复标题、不能帮助用户判断的空话。
- 引用素材的悬停预览必须与引用生命周期同步：删除引用、断开连线、删除来源或重绘引用列表时立即关闭并销毁旧预览，不能依赖已经被移除元素的 `mouseleave` 事件。
- 执行参数头部固定分区：左侧依次为标题、模型说明、更多设置；右侧依次为可截断的模型名称、独立数量按钮和运行按钮。帮助与设置按钮同尺寸、同间距，数量按钮必须预留固定轨道，不得覆盖模型名称或运行按钮的点击区域。
- laohu 图片家族按精确 ID 和已审阅能力资料映射：`laohu-image-g-v2-lowprice`、`laohu-image-g-v2.5-flare`、`laohu-image-g-v2.5-lowprice`、`laohu-image-g-v2.5-sunburst`、`laohu-image-g2-i2i`、`laohu-image-g2-t2i` 显示为 GPT Image；真实 `laohu-image-gk-*` 显示为 Grok Image。未知的 `laohu-image-g-v9-*` 不按 `g` 前缀猜家族，缺少证据时保留原提供方/未确认身份，并以真实 ID 辅助识别，不编造质量、用途或版本。

### 4.4 API 设置

- 页面使用“左侧平台导航，右侧当前平台配置”的双栏结构。
- 左侧平台列表保持窄而清楚，平台名称、配置状态和 CLI 标识分层显示。
- 右侧每个设置区使用一个有明确标题的面板，面板内部使用分组和留白，不把所有字段放进连续长表格。
- API Key、地址、模型 ID 等技术信息使用更清楚的标签和等宽字体，帮助文字放在字段下方。
- “保存”“验证地址”“拉取模型”属于主要操作，按钮高度、图标和对齐方式必须统一。
- 模型列表使用可扫描的行或小组，不使用过度装饰的模型卡片。删除、预检和启用状态要放在同一行的尾部。
- Hypit 模块级六用途生成配置使用共享画布编辑。入口按钮中英文为“打开画布编辑” / “Open canvas editor”和“重置配置” / “Reset configuration”；打开在同一全屏编辑面，重置只清空配置图节点与连线。右侧抽屉用于添加六种用途；再次选择已经存在的用途时，应聚焦已有输出节点，不能将抽屉本身当结果面板或重复创建节点。允许通过同源 iframe 复用画布页面，但同一项目只能有一份节点图、模型配置与任务执行链；Hypit 原生作品工程及其 Studio/Comments 仍保持原样，不转成画布工程。
- Hypit 配置图的 API 生成模型候选须满足用户启用、完整模型契约、节点输入/输出要求及对应 Hypit 用途，沿用 `hypit_profile_reasons`；不适用的模型在 Hypit 生成选择器中隐藏，后端也拒绝不符合条件的请求，但不从普通画布的全局启用列表、共享档案或配置中删除。查询、下载、放大、增强、字幕等专用工具不能作为生成模型；普通画布的独立处理节点仍可接在实际生成节点之后。AI 应用/工作流仍由用户选择用途，不从名称、Schema 或声明标签推断适用性，执行后按真实结果类别和宿主契约检查。工作流执行定义和安全 Schema 不得屏蔽画布已有处理步骤；依赖图缺少实际生成输入时明确报不可调用错误。
- 节点来源可选择 API 模型或已配置 AI 应用/工作流，来源切换只改未保存草稿；工作流安全 Schema 用于显示字段，不用于猜测输出用途或强制绑定。用户可将 AI 应用连接到任意用途，实际执行后依据真实结果类别检查是否满足目标。取消时保留原已保存选择，错误必须指出不匹配原因。
- 固定端口每个输入只接受一条连接；新相容连接替换原连接，静态类型不兼容时在连线提交前拒绝。动态 AI 应用端口按实际 Schema 显示，运行结果仍须做类别校验。锁只阻止 Hypit 自动替换素材绑定；多个明确 `@` 引用按原顺序保留，只有来源或目标确实无法定位时才提示歧义并保留现有引用。
- 端口的红、黄、绿状态分别表示未连接、已连接未验证、当前配置链验证通过。红态不可执行，黄与绿都允许执行；相关节点、参数、素材或连线变化后，旧绿态立即失效。颜色旁必须提供文字或图标，并保留可行动错误信息。中英文语义一致，键盘和窄屏操作不能丢失用途抽屉、输出节点、保存及错误入口。
- 推荐 API 只显示管理员明确认可的平台。合作入口可以保留，但不能让未经认可的平台看起来像推荐平台。

### 4.5 素材库和设置页

- 素材预览优先于说明文字，媒体类型通过真实预览、播放控件和文本内容表达。
- 文件名过长时单行省略，悬停或详情区显示完整名称。
- 上传、替换、保存、删除等动作使用明确的动词，不使用内部实现名称。
- 大型设置使用分组折叠或两列网格，避免一页出现无尽纵向表单。

## 5. 交互和动效

- 动效只表达四类信息：层级出现、状态变化、用户反馈和媒体播放状态。
- 弹层使用短暂的透明度和位移动效，不能延迟用户操作。
- 按钮按下时只做轻微的 `scale(.985)` 或下移反馈，不能改变布局尺寸。
- 参数弹层、菜单、日志和错误提示必须有明确的关闭行为，`Esc` 和点击外部区域都应有效。
- 所有动效必须尊重 `prefers-reduced-motion: reduce`，在减少动效模式下退化为即时状态切换。
- 视频和音频预览只在用户悬停或明确播放时启动，不能在画布移动时重新加载媒体。
- 生成中的动画按任务独立持续播放，画布重绘、选中、拖动、缩放不能重置相位。以中性底色与局部柔光/细光点表示处理状态，位置缓慢随机变化，禁止大面积混色毛玻璃透出画布网格。旧结果只压暗，不用强模糊抹掉内容；任务结束释放动画，减少动态效果时暂停移动。

## 6. 文案与国际化

- 中文界面优先使用用户能直接理解的功能名称，例如“上传素材”“画面比例”“生成数量”。
- 参数名称、帮助内容、错误提示和按钮不能只显示英文。已有语言切换时，中文和英文必须同步维护。
- 可见文案避免把平台内部字段直接暴露给用户。模型 ID 可以作为辅助信息，但不能替代人类可读名称。
- 不使用装饰性口号、假数据、无意义标签、过度技术化的英文缩写或长段解释。
- 一个操作只保留一个主按钮名称，避免同一页面出现多个表达相同意图的 CTA。

## 7. 响应式与可访问性

- 桌面端保证导航单行，窗口变窄时优先收缩间距和标签，再进入纵向布局。
- 页面默认自动适配应使用真实响应布局，根据可用视口调整容器、网格和断点；不得把固定设计尺寸的整页 `body` 自动 `transform: scale()` 当作响应式，避免文字、控件与点击目标一并缩小。保留用户明确选择的手动缩放，并让自动适配与手动缩放保持不同语义。
- 参数网格在小屏幕下变为单列，弹层宽度不得超出视口。
- 参数入口保持单行等高，平台、模型、运行模式按较窄/较宽/适中分配空间；长模型名可省略显示，悬停与展开列表提供完整名称。弹层内参数名和选项使用精炼短标签，说明放入帮助，不裁切文字或遮挡相邻控件。默认项独占整行，其余枚举及有限范围值排列为等高点选格。
- 所有按钮和图标按钮有可读的 `title` 或 `aria-label`。
- 焦点环必须清楚可见，不能只靠颜色区分。正文文字与背景至少满足 WCAG AA 对比度：普通文字 4.5:1，大号文字 3:1；浅黄和朱红主要用作有限面积强调，不以低对比小字单独传达信息。
- 不依赖颜色作为唯一状态提示。启用、错误、加载和不可用状态同时使用文字或图标。

## 8. 禁止事项

- 不使用无主次的通用渐变、无语义光晕、装饰性网格线或大面积玻璃效果作为默认设计；有限色彩过渡只有在明确服务层级或焦点且不损害对比时才可使用。
- 不让画笔、颜料、纸纹等装饰压住作品、阅读内容或操作入口；画室素材只点到工作区留白、空状态或边缘。搜索框、搜索建议、导航、筛选、菜单和创建等高频操作区不得被白底贴图、不透明图片卡或装饰遮罩覆盖、压住或挤占。
- 不把所有内容做成卡片，不在卡片里面继续套卡片。
- 不把所有参数直接罗列成长表单，不让每个模型切换后出现一套完全不同的控件样式。
- 不使用大型齿轮、过大的圆形问号或与标题不对齐的装饰图标。
- 不把外部产品的 UI、命名和结构直接复制到本项目。
- 不为了视觉修改删除已有功能、破坏历史画布或改变 API 请求字段。
- 不在没有官方 Schema 证据时添加可运行参数，不伪造模型价格。

## 9. 新 UI 的执行流程

1. 阅读本规范和相关页面现有 CSS、HTML、JavaScript，先列出可保留、需修复、缺失和淘汰的部分。
2. 按 `frontend-design` 明确目的、用户、视觉方向和一个最值得记住的交互重点。
3. 按 `design-taste-frontend` 完成设计读、刻度判断、令牌审计和反模板化检查。用户要求 Pinterest 或其他外部视觉参考时，核对实际图片及可查到的原始出处，明确它支持的是色彩关系、面积、材料或布局中的哪项判断；色板案例不能证明可读性或创造力效果，仍须回到本项目的真实页面与对比度验证。
4. 优先复用现有组件和数据结构，只新增真正缺失的结构。
5. 先完成真实页面，再在浏览器验证浅色、深色、窄窗口、弹层层级、键盘焦点和错误状态。
6. 修改完成后回看所有可见文字、间距、对齐和控件命中区域，再更新本规范或相关组件规则。

## 10. 发布前检查

- 页面是否仍然是创作工具，而不是营销页面？
- 五种主题身份是否保持独立于浅/深外观？主题面板只提供浅/深入口；旧 `system` 偏好能否原样读取且在仅打开面板时不被改写？默认 `studio-violet` 是否仍只是一组默认配色，而非全项目硬编码？
- 各主题的颜色搭配、面积和信息层级是否舒服、清楚？品牌色、主要操作、创作焦点和状态色是否各司其职，而不是争同一个视觉焦点？
- 字体、圆角、边界、阴影和滚动条是否遵循统一令牌？
- 参数是否按统一骨架显示，弹层是否从上方展开并高于其他内容？
- 当前值、默认值、可选参数和不可用状态是否表达清楚？
- 中文和英文是否同步？按钮文字是否一行完整显示？
- 浅色和深色主题是否都可读？
- 是否尊重原有功能、数据、节点和 API 字段？
- 是否完成真实浏览器验证，而不是只看静态代码？


## 素材库交互补充

结果分类固定为全部、文本、图片、视频、音频、音乐；音乐是音频文件的用途分类，收藏后继续显示音符，语音显示波形。视频展示真实首帧，服务端预览不可用时由共享 `StudioMedia.firstFrame` 读取原视频，避免出现只有播放图标的黑卡。

批量管理统一使用一个带选中状态的“全选／清空”切换按钮，后接下载和删除。预览在黑色背景顶部两端说明 ESC 和点击背景的退出方式。复制反馈放在触发操作附近，不以正文选区或遮住内容的大浮层表示成功。

素材库普通复制与画布复制原素材快捷键复用 `static/js/media-ui.js` 和 `/api/system-clipboard`。单图片同时提供图片数据和原文件；多媒体提供有序文件集合，纯文本提供正文。目标应用决定是否接收多个文件或某种媒体，不能把链接复制当作原文件复制成功。macOS 使用 [NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard)，Windows 使用持久化的 [Clipboard.SetDataObject](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.clipboard.setdataobject)。Windows 实际粘贴仍需在 Windows 桌面验收，跨平台单元测试不能替代真实桌面测试。


数值选择统一为滑块配合数值输入框，允许键盘直接改值；输入框、滑块和提交值同步。模型允许自由画面比例时提供常用比例和自定义输入，接口已有枚举时严格使用枚举。顶部画布工具采用 32px 高度、11px 标签和 14px 图标，在窄窗口保留图标入口，把空间留给画布。

画布迁移统一使用 ZIP：workflow.json 保存节点、连线、默认设置与资源映射，resources/ 保存带原始名称的媒体。用户在新画布点击工作流并导入整个 ZIP 即可，无需解压。导入重写资源 URL、历史版本和节点引用；不包含 API Key。纯 JSON 只适合同一资源环境或不含媒体的结构交换。

同类参数必须共用实现：五类生成节点、生成信息和 Agent 默认设置复用能力参数渲染器；RunningHub AI 应用与 ComfyUI 的官方字段先转换为相同的参数描述，再交给该渲染器。转换只处理标签、类型、选项和约束，不改变平台真实字段键或选项提交值。布尔、枚举、范围数值和自由输入不得各自新增一套近似表单。

素材处理中的笔刷、间距和音量，复用成对的滑块与数值输入绑定。直接输入经原滑块的事件提交，与拖动走同一业务校验；输入未完成时保留草稿，失焦恢复最后有效值。已有成对控件不重复添加。导入资源包后自动定位到导入节点，保持原有相对布局。

音视频编辑统一为顶部名称和唯一关闭入口、中部媒体及时间轴、底部集中工具栏。播放与试听、音量与倍速、裁剪与提取按功能组排列，统一高度、背景、边界和间距；窄屏按完整组换行，禁止孤立按钮独占空白面板。首帧、当前帧、尾帧各保留一个提取入口，下载在生成后的素材节点操作。

时间轴显示真实波形、渐变播放进度、起止拖柄与独立播放头，支持点击定位、拖动和选区试听。无法解码波形时显示简短说明，仍可选择时间。验收必须查看明暗主题及窄屏截图，同时检查同一操作是否出现重复入口。

创作进度的固定控制融入顶部标题行中央：透明底、无边框、不突出容器。以原位圆圈/双横杠表达固定/自动收起，不使用滑动开关或位移图标。保留足够点击区域和键盘焦点提示；点击解锁不打断当前悬停查看，鼠标移出后才自动收起。
