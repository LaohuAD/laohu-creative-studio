# 平台适配说明

能力档案描述“模型能做什么”，平台适配器负责“怎么调用”。两者不能互相替代。

## 平台职责

| 平台 | 适配协议 | 档案来源 | 当前维护重点 |
| --- | --- | --- | --- |
| laohu | OpenAI 兼容及专用媒体接口 | 官方 `/v1/models`、已验证历史档案、项目适配器 | 文本、图片、视频、音频的操作模式和字段依赖 |
| RunningHub | RunningHub API、远端应用/工作流字段 | 官方模型注册表、远端字段快照、项目适配器 | 动态输入编号、字段类型、应用和工作流参数 |
| ModelScope | OpenAI 兼容 | 当前项目请求、官方模型资料 | 任意新增模型先进入待确认，不能从名称推断图生图 |
| 火山引擎 | 方舟协议 | 官方 Schema、项目适配器 | 用户添加模型后再建立档案；当前没有默认模型 |

## 统一运行链路

```text
画布连接的素材
→ 推导统一任务语义和输入角色
→ 能力档案筛选产品模型家族
→ 路由到唯一任务变体和真实模型 ID
→ 生成平台无关的标准请求
→ 后端按档案校验输入和参数
→ 平台适配器转换字段、上传和异步任务
→ 统一登记结果和原始追踪信息
```

前端不得把 RunningHub 的 `fieldName`、laohu 的请求字段或平台轮询细节当作通用节点字段。平台变化优先修改适配器和平台档案，节点只消费统一语义。

同一个产品模型可以对应多个平台接口。例如视频模型可分别提供文生、首帧、首尾帧、多参考、编辑和延长变体；用户只选择产品模型家族，系统依据操作模式和输入角色选择真实接口。国内站、国际站、VIP 或低价通道属于部署路由，不能拆成新的画布平台或重复模型家族。

目录接口返回模型名称不代表适配完成。平台目录、能力档案和运行适配器必须分层：目录负责发现，能力档案负责证明，适配器负责转换和执行。静态请求快照通过时只标记 `contract_validated`；只有获得授权并完成真实结果落地验证后，才能标记 `runtime_verified`。

自定义平台使用受 Schema 约束的 Provider Manifest 描述目录、模型家族、任务变体、能力、请求映射和任务协议。Manifest 不允许内嵌任意脚本；AI 根据第三方文档生成的内容只能作为草稿，必须经过 Schema、语义、域名安全和请求快照校验后启用。

## 证据来源

- laohu 人类文档入口：`https://api.lao-hu.com/`
- laohu 鉴权模型目录：`https://api.lao-hu.com/v1/models`
- RunningHub 模型注册表：`https://raw.githubusercontent.com/HM-RunningHub/ComfyUI_RH_OpenAPI/main/models_registry.json`
- 本地用户模型入口：`data/api_providers.json`
- 本地请求实现：`main.py`、`static/js/smart-canvas.js`

2026-09-12 已恢复并核对官方 [llms.txt](https://api.lao-hu.com/docs/llms.txt)。本次补齐 Image G v2.5 三个通道、新文本模型、MiniMax-H3 V2、Suno V6 翻唱/续写/自定义模型、Seedream 5、VOSR2 和 FlashVSR 的档案与协议。MiniMax 保留角色与驱动音频字段；创建请求只发送一次，不确定受理时按 X-Task-Id 查询。Suno 自定义模型接受 6–24 条音频并将 model_id 保存为文本素材。

当前 laohu 完整目录 262 项：259 项具有可运行档案，0 项缺少档案，3 项标记适配器缺口（Hunyuan3D 文生/图生 3D、Kling 唇形 TTS）。3D 文件尚不属于画布四种素材类型，不能用视频或图片假装已经支持；Kling 唇形 TTS 仍缺少完整请求适配。这些项不会被标成可以生成。可运行档案是无付费协议验证结论，不等同于本账号已实付生成成功。

用户启用模型列表保持独立：升级档案不自动加回用户删除的模型。要使用新模型，在 API 设置主动拉取并勾选，再到画布或 Agent 默认设置中选择。

### laohu Image G 身份映射修正（2026-10-05）

统一候选投影曾将 `laohu-image-g-v2-lowprice`、`laohu-image-g-v2.5-{flare,lowprice,sunburst}` 和 `laohu-image-g2-{i2i,t2i}` 按宽泛 `laohu-image-g` 子串归进 Grok Image。现改为只将这六个有现存精确档案／适配依据的 ID 归到 GPT Image；真实 `laohu-image-gk-*` 仍归 Grok Image。没有证据的 `laohu-image-g-v9-*` 不因 `g` 前缀自动归入任一家族。

v2.5 的档案仍保留 `text_or_reference_to_image` 输入用途，Flare 与 Sunburst 作为原始渠道词显示，不据名称推断质量；`lowprice` 保留现有低价渠道标注。G2 的现有动态 profile 区分文生图和图生图，图生图仍要求参考图片。此次只纠正身份投影，不更改模型 ID、请求映射、参数契约或用户启用清单。画布和 Hypit 使用同一 `/api/model-capabilities.options` 投影，并分别按各自槽位过滤。

本轮访问 laohu 鉴权目录与文档入口均返回 HTTP 403，因此以上归类复用仓库现有能力档案和 `dynamic_profile_for_model()` 的内部映射，不代表本轮重新拉取目录或完成新的官方认证；Flare、Sunburst 的质量含义也仍未确认。

### 即梦 5.0 Pro 分辨率修正（2026-09-12）

用户实际失败 logid `202609122315201921680012536243EAB`：服务端拒绝 `resolution_type=1k`，明确接受 `1.5k/2k/4k`。5.0 Pro 的静态档案、动态目录与提交前校验均按此契约提供 **1.5K、2K、4K**；文生图和图生图选择 1.5K 时都原样提交 `--resolution_type=1.5k`。本机 CLI 旧帮助仍列 `1k/2k/4k`，这是资料冲突，不能据此取交集删掉服务端支持的 1.5K。未指定分辨率的既有本地兜底仍为 2K；旧 1K 提前拒绝，不自动改用户选择、不自动重试付费请求。3.x、4.x 等继续按自己的模型契约，不增加 1.5K。本次验证目录和模拟 CLI 参数传递，没有进行真实付费生成。

统一要求只约束控件格式、布局与操作方式；选项、数值范围及提交值必须按具体平台、模型和运行模式分别维护。

1.5K 修正验收：155 项模型能力回归通过；真实 Chrome 节点参数显示 `1.5k / 2k / 4k`，本机 `/api/model-capabilities` 返回相同选项。模拟 CLI 覆盖文生图/图生图、`resolution`/`resolution_type` 两种映射入口和大小写规范化。未调用付费模型，未更改 CLI 安装或启动脚本，Windows 未实机测试。

### 供应商目录与画布候选复核（2026-10-05）

laohu 鉴权 `GET /v1/models` 本轮 HTTP 200，返回 274 个唯一模型 ID。现将 274 条供应商原始记录原样保存在 `ai-money-catalog.json` 的 `source_models` 中；已有按节点分类列表和详细能力档案原样保留，避免把缺少 `supported_endpoint_types` 的目录项猜成某类生成模型。与旧分类列表相比，原始源新增的 9 项为 `dola-seedream-5.0-flash-{i2i,layer-decomposition,t2i}`、`laohu/g6-{luna,sol}`、`seedream-v5-flash-{i2i,layer-decomposition,t2i}`、`typesafe/jev-1.13`。其中 g6 与图层拆分项沿用已有档案；`typesafe/jev-1.13` 只有 `decisions` 类型，不能据此建画布生成档案。另有 3D、TTS 等目录项不能因为返回模型 ID 就当作当前画布生成能力：`hunyuan3d-v3.1-text-to-3d` 与 `hunyuan3d-v3.1-image-to-3d` 仍是未接入的 3D 输出，`kling-lip-sync-tts` 是文本输出，不是音频生成。未据目录差异批量启用模型。

官方 [laohu 完整 API 文档](https://api.lao-hu.com/docs/llms.txt) 本轮 HTTP 200，明确列出四个此前无档案的 Seedream V5 Flash 端点：国内 `seedream-v5-flash-{t2i,i2i}` 与海外 `dola-seedream-5.0-flash-{t2i,i2i}`。四项均按文档登记为 `/v1/image/generations`：提示词 5–5000 字符，分辨率 `1k/1.5k/2k`，输出格式 `jpeg/png`，宽高各 240–8192 且仅在未指定分辨率时生效；图生图需要 1–10 张参考图、单张不超过 30 MB。档案保留为未启用状态。运行时适配器已有相同路由和 `metadata`/`images` 请求映射，没有为此扩展另一路由或进行真实生成探测。

RunningHub 当前上游以 [官方原始注册表](https://raw.githubusercontent.com/HM-RunningHub/ComfyUI_RH_OpenAPI/main/models_registry.json) 为准（2026-10-05，commit `8f9c858e7e631a1c1c49df0c4defd77fdd690dd4`）：422 项，含图片 107、视频 228、音频 20、文本 51、3D 16 项。上游 `developer-kit/model-registry.public.json` 当时只有 383 项；原始注册表多出 39 项（图片 12、视频 24、文本 3），没有只存在于旧派生目录的项目。两源共有的 11 项字段 Schema 已不同，现由原始注册表的精确 `params` 覆盖旧地域快照；其中 Qwen Image 3.0 Pro 的 `SIZE` 带有固定 `options` 时按原枚举呈现，保留其 15 个真实值和默认值，不把它当自由文本。详情见 [RunningHub 官方模型页（Global）](https://www.runninghub.ai/call-api/search-api/standard-model) 和 [CN](https://www.runninghub.cn/call-api/search-api/standard-model)。RunningHub 的产品/通道名只证明该服务商目录中的条目，不代表 OpenAI 等模型厂商直接发布或背书该名字。

按用户明确要求，只将以下 8 个完整契约模型加入 RunningHub Global 图片选择：`gpt-image-2.5/{flare,sunburst}/{text-to-image,image-to-image}/{economy,stable-token}`；CN 站与其余目录新增项保持原设置。运行时模型能力接口已返回 8 个 `ready/runnable/selectable` 候选，均标记 `region=global`。旧地域目录中仍有四个已保存但无字段 Schema 的名称，不得显示为可运行生成项：图片 `f-dev`、`f-dev-lora`；视频 `kling-v3.0-4k-motion-control`、`ltx-2-19b/text-to-video-lora`。其目录身份与用户选择保留，等待上游完整 Schema。
